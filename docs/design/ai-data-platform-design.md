## 一、产品定位与目标

### 1.1 产品定位
**AI智能数据分析师（Agent）** —— 以"智能副驾驶"模式与数据运营人员协作的AI数据分析中台。

### 1.2 核心目标
- **零影响线上**: 任何操作都不影响生产环境和线上产品
- **对话即分析**: 用自然语言替代SQL，降低数据分析门槛
- **主动发现问题**: AI主动监控数据异常，及时提醒
- **越用越懂你**: 持续学习业务经验和工作习惯
- **快速验证，无缝迁移**: 本地Docker一键启动，验证后一键部署到私有服务器

### 1.3 目标用户
- 数据运营人员、产品经理、业务负责人
- 需要频繁查询和分析业务数据，但不想写SQL的非技术同学

## 二、核心功能模块

### 2.1 AI智能对话分析（核心）

#### 功能描述
用户通过自然语言与AI对话，完成数据查询、分析和洞察。

#### 核心能力
| 能力 | 说明 | 示例 |
|------|------|------|
| 自然语言转SQL | 理解用户意图，自动生成SQL | "最近7天新注册用户有多少" → `SELECT COUNT(*) FROM users WHERE created_at >= DATE_SUB(NOW(), INTERVAL 7 DAY)` |
| 多轮对话分析 | 支持上下文关联的追问 | "按渠道拆分" → AI记住上文是"新注册用户" |
| 数据解读 | 不仅给数字，还给业务洞察 | "本周次日留存45.2%，比上周下降3.1%，周三有明显下跌" |
| SQL纠错 | 用户手写SQL出错时，AI帮助诊断 | "这个SQL报错了，帮我看看" |
| 智能推荐 | 基于当前数据，推荐下一步分析方向 | "建议你看一下周三的渠道分布，可能与版本发布有关" |

#### 交互流程
```
用户: "看看这周留存率怎么样"
AI: "本周次日留存率为 45.2%，比上周下降 3.1%。我注意到周三有一次明显的下跌，
     可能与当天发布的新版本有关。需要我深入分析哪个维度？"
用户: "按渠道拆分看看"
AI: [生成渠道留存率对比图表 + 数据解读]
用户: "把上周的数据也加上，做对比"
AI: [生成双周渠道留存率对比趋势图]
```

#### 核心能力
| 能力 | 说明 |
|------|------|

| 静默期 | 支持设置告警静默时间，避免打扰 |

#### 告警规则示例
```yaml
规则1: 日活下降超过10%
  指标: DAU
  条件: 环比下降 > 10%
  检查频率: 每天 09:00
  告警级别: 紧急

规则2: 新用户注册异常
  指标: 日新增用户
  条件: 低于过去7天平均值 20%
  检查频率: 每小时
  告警级别: 警告

规则3: 核心功能使用下降
  指标: 消息发送量
  条件: 连续3天下降
  检查频率: 每天
  告警级别: 关注
```

3. 反馈学习: 用户对AI回答点赞/踩，调整回答策略

### 3.3 数据安全设计（核心）

#### 3.3.1 只读保障
```python
# 后端强制只读模式
READ_ONLY_KEYWORDS = ['INSERT', 'UPDATE', 'DELETE', 'DROP', 'TRUNCATE', 'ALTER']

def validate_read_only(sql: str):
    """确保所有SQL都是只读查询"""
    upper_sql = sql.upper()
    for keyword in READ_ONLY_KEYWORDS:
        if keyword in upper_sql:
            raise ValueError(f"检测到危险操作: {keyword}，仅支持只读查询")
```

#### 3.3.2 查询限制
| 限制项 | 配置 | 说明 |
|--------|------|------|
| 超时时间 | 30秒 | 超自动终止 |
| 最大返回行数 | 10000行 | 防止大数据量拖垮 |
| 并发查询数 | 10个 | 防止并发过高 |
| 查询频率 | 每分钟最多60次 | 防止刷接口 |

#### 3.3.3 连接安全
- 使用只读账号连接MySQL（`SELECT`权限 only）
- 数据库连接使用SSL加密
- 敏感配置（密码、API Key）使用环境变量，不写入代码

## 八、附录

### 8.1 技术选型理由

**为什么选择Python全栈而非Java？**
- AI/ML生态Python是绝对主流，LangChain、LangGraph等框架都是Python优先
- 快速验证阶段，Python开发效率更高
- 后期如需Java团队接手，API层可以独立，前端和AI层不变

**为什么选择Next.js而非纯React？**
- 全栈框架，前后端可以放在一个项目里，部署简单
- 自带API路由，MVP阶段无需单独部署后端
- 后期可以拆分，不影响架构

**为什么MVP用SQLite而非PostgreSQL？**
- 零配置，Docker启动即用
- 平台数据量不大，SQLite完全够用
- 后期迁移到PostgreSQL只需改连接字符串

### 8.2 预估成本

| 项目 | MVP阶段 | 生产阶段 |

| MySQL只读从库 | 开发团队提供 | 开发团队提供 |
| 总计 | ~50元/月 | ~400-700元/月 |
